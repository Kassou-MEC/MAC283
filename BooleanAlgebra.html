Part 1 · Foundations

What is Boolean Algebra?

Boolean Algebra is a branch of mathematics that deals with binary variables and logical operations. It forms the basis for digital circuit design and computer logic.

Key features

  • Variables take only two values: 0 (false / OFF / LOW) and 1 (true / ON / HIGH)
  • Three basic operations: AND ( · ), OR ( + ), NOT ( ' or ¬ )
  • Named after George Boole (1854) — a century before computers existed!
Real Life

You already think in Boolean

"I'll go outside IF it's sunny AND I'm free."

"The light is on IF switch 1 OR switch 2 is flipped."

"The door unlocks IF the badge is NOT expired."

Every one of these sentences is a Boolean expression. Circuits just make them electric.

Part 1 · Foundations

The Three Basic Operations

AND  ( · )

Output is 1 only if ALL inputs are 1.

A · B = 1 if A = 1 AND B = 1

🔒 Think: a bank vault that needs two keys turned at the same time.

OR  ( + )

Output is 1 if at least one input is 1.

A + B = 1 if A = 1 OR B = 1 (or both)

🚪 Think: a hallway light with switches at both ends — either one works.

NOT  ( ' or ¬ )

Output is the inverse of the input.

A' = 1 if A = 0

🌗 Think: a streetlight sensor — light turns ON when it is NOT daytime.

⚠️ Careful: · looks like multiplication and + looks like addition — and for 0s and 1s they mostly behave that way, except 1 + 1 = 1 in Boolean (not 2). There is no "2" in this universe.

Part 2 · Simplification

Common Boolean Algebra Laws

These laws let us shrink expressions — fewer terms means fewer gates, cheaper chips, and less heat.

LawExpressionIn plain English
IdentityA + 0 = A  ·  A · 1 = AAdding "never" or requiring "always" changes nothing
NullA + 1 = 1  ·  A · 0 = 0OR with "always true" is always true; AND with "impossible" is impossible
IdempotentA + A = A  ·  A · A = ARepeating a condition adds no information
Involution(A')' = AA double negative cancels out
ComplementA + A' = 1  ·  A · A' = 0Something is either true or false — never both, never neither
AbsorptionA + AB = A  ·  A(A + B) = AThe bigger term "swallows" the smaller one
DistributiveA(B + C) = AB + ACWorks just like algebra — factor and expand
DeMorgan's(AB)' = A' + B'  ·  (A + B)' = A' · B'Break the NOT, flip the operator

Real-Life Example #2

🛗 DeMorgan's Law in the Wild — The Elevator

An elevator moves (M = 1) only when it is NOT true that the door is open or it's overloaded:

M = (Door + Overload)'

Apply DeMorgan's: (A + B)' = A' · B'

M = Door' · Overload'

Same behavior — but the second form says it more naturally: "door closed AND weight OK." Engineers pick whichever form uses fewer / cheaper gates.

Common Mistake Alert

(A · B)'  ≠  A' · B'

Students often just "push the NOT inside" without flipping the operator. Check with A=1, B=0:

ExpressionValue
(1 · 0)' = 0'1
1' · 0' = 0 · 10

Different answers → not equal! The NOT must flip · into + as it distributes: (A · B)' = A' + B'.

Part 3 · Karnaugh Maps

What is a Karnaugh Map (K-Map)?

  • A visual method for simplifying Boolean expressions
  • Introduced by Maurice Karnaugh at Bell Labs in 1953
  • Converts truth tables into simplified logic expressions
  • Commonly used in digital circuit design to reduce the number of logic gates
  • It's a grid where adjacent cells differ by exactly one variable — that's the magic ingredient

Why not just use Boolean algebra?

  • Algebra gets tedious and error-prone for 3+ variables
  • K-Maps give systematic grouping — no creativity required
  • Minimization without formulas or long derivations
  • Sweet spot: 2 to 4 variables
Analogy

K-Map = seating chart for logic

Imagine arranging students so that any two neighbors differ by only one answer on a quiz. Once seated, whole rows of agreement jump out visually.

A K-Map does exactly this with truth table rows: it seats them in Gray code order so patterns you'd need algebra to find become rectangles you can circle.

Circle the rectangle → read off the simplified term. That's the whole method.

Reading the raw expression

From the two rows where A = 1:

  • Row (M=0, D=1) → term M'D
  • Row (M=1, D=0) → term MD'
A = M'D + MD'

The apostrophe means NOT: M' = "motion sensor OFF", D' = "door closed". Each product term includes every variable, matching its exact row condition.

⚠️ Why the weird column order?

Watch the headers: 00 → 01 → 11 → 10. Between any two neighbors, only one bit changes. That's Gray code.

If we used normal counting (00, 01, 10, 11), the jump 01→10 changes two bits — and adjacency would lie to you. Groups you circle would not correspond to a single variable canceling.

Bonus: the map wraps around — the leftmost and rightmost columns are also neighbors, like a cylinder.

Reading the Groups — The Payoff

A

Overlapping groups are allowed and encouraged — m7 belongs to both.

Part 3 · Two Standard Forms

SOP vs POS

SOP — Sum of Products

  • Write AND terms for every row where F = 1
  • Then OR (sum) them together
  • K-Map: place and group the 1s (minterms)
F = T·L'·B + T·L·B' + T·L·B

🗣️ Reads as: "Fan is ON when condition 1 OR condition 2 OR condition 3 is true." → natural for triggers, alerts, actuators.

POS — Product of Sums

  • Write OR terms for every row where F = 0
  • Then AND (multiply) them together
  • K-Map: place and group the 0s (maxterms)
F = (T+L+B)(T+L+B')(T+L'+B)(T+L'+B')(T'+L+B)

🗣️ Reads as: "Fan is OFF unless all safety conditions pass." → natural for safety systems, locks, suppressors.

Same function, two dialects. Pick the one with fewer terms: lots of 1s in the table → POS is shorter; few 1s → SOP wins (like our fan: 3 ones vs 5 zeros).

Part 3 · Comparison

Boolean Algebra vs Karnaugh Map

AspectBoolean AlgebraKarnaugh Map
✏️ MethodRules & theoremsVisual grouping
🧠 ThinkingManually apply laws (combine, factor, cancel)Just group adjacent 1s or 0s
📝 NotationAND, OR, NOT (A·B + C)Same notation
📐 EffortGets complex with 3+ variablesMuch easier for 2–4 variables

They're partners, not rivals: the K-Map finds the groups; Boolean algebra explains why the grouping works (each group of 2ᵏ cells is repeated applications of XA + XA' = X).
