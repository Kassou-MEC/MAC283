01 · Warm-Up

Read the Contract Out Loud

Before writing assembly, learn to read it the way the CPU does: destination first, sources next, memory in base(offset) form. Pick any instruction below and watch it happen to real register values.

Reading trick that works every time: say "gets" for the first comma. add $t0, $s1, $s2 → "$t0 gets $s1 plus $s2." lw $t0, 8($s0) → "$t0 gets the word at $s0 + 8." Once "gets" is automatic, no instruction is confusing.

02 · Encoding I

Worked Example: Assemble sub by Hand

Machines don't read mnemonics — the assembler converts them to 32 bits. On the exam, you are the assembler. Let's encode sub $s0, $t3, $t4 step by step.

The recipe never changes: 1) name the format, 2) look up the numbers (opcode/funct, register numbers), 3) write each number in binary at its fixed width, 4) concatenate, 5) group into 4-bit nibbles → hex. Five steps, every time, for every R-format instruction ever.
Format? Three registers, no memory, no constant → R-format: op·rs·rt·rd·shamt·funct.
Numbers. sub → op = 0, funct = 34. Registers: $s0 = 16, $t3 = 11, $t4 = 12. Careful: assembly order is rd, rs, rt — but the encoding order is rs, rt, rd.
Binary at fixed widths. op=000000 · rs($t3)=01011 · rt($t4)=01100 · rd($s0)=10000 · shamt=00000 · funct(34)=100010
Concatenate: 0000 0001 0110 1100 1000 0000 0010 0010
Hex nibbles: 0x016C8022 — done. That 8-digit number IS the instruction; burn it into a ROM and any MIPS chip on Earth executes "$s0 gets $t3 minus $t4."

THE CLASSIC TRAP

Students write the fields in assembly order (rd first) instead of encoding order (rs, rt, rd). The mnemonic is for humans; the bit layout is for the decoder — and they disagree on purpose. Check yourself: rd lives in bits 15–11, the middle of the word.

03 · Decoding

Disassembly: Read a Mystery Word

Now the reverse — you find 0x02324020 sitting in memory. What does the machine do with it? Exactly what a disassembler (or a reverse engineer) does: slice fields at fixed positions.

Decoding starts at the opcode (top 6 bits): if it's 000000, you have R-format and the funct field (bottom 6 bits) names the operation. Any other opcode names the operation directly and tells you the format. First 6 bits → everything else follows.

Try word #4 (0x2129FFF8): the immediate field reads FFF8 — which is −8 in 16-bit two's complement, so the instruction subtracts by adding. Your two's-complement drills are exactly what separates "addi with 65528??" from the correct read. Malware analysts, game modders, and console emulator authors do this slicing all day — an emulator is just this slide running a billion times per second.
04 · Arrays

The Array Pattern: A[i] = A[j] + A[k]

Every array statement compiles to the same skeleton: load the sources, compute, store the destination — with byte offsets 4× the index. Move the sliders and watch the compiler in your head become code on the screen.

Only the offsets change when the indices change — the instructions and their order never do. That's what "pattern" means: memorize the skeleton once, then array problems become multiplication by 4.

05 · A Famous Four Lines

Worked Example: swap(A, k)

Swap A[k] and A[k+1] — the inner move of bubble sort, and the most famous four instructions in the Patterson & Hennessy textbook. In C you'd need a temp variable; in MIPS, registers are the temp variables.

The trick: load both values onto the bench first, then store them back crossed. No third copy needed — $t0 and $t1 hold both originals while memory is being overwritten. The bench remembers while the warehouse changes.

COMPILE THIS · k→$s0, base of A→$s3

// C source temp = A[k]; A[k] = A[k+1]; A[k+1] = temp;
Address math first. A[k] lives at $s3 + 4k. Compute 4k with a shift: sll $t1, $s0, 2 (shift left 2 = ×4, one cycle — new tool, straight from your binary unit) then add $t1, $t1, $s3 → $t1 now points at A[k].
Both values to the bench: lw $t0, 0($t1) (A[k]) and lw $t2, 4($t1) (A[k+1] — just 4 bytes further, no new address math).
Store back crossed: sw $t2, 0($t1) and sw $t0, 4($t1). The "temp variable" was $t0 all along.
The bill: IC = 6 (sll, add, lw, lw, sw, sw). Cycles = 1+1+4+4+3+3 = 16. Bubble sort calls this millions of times — now you know why sorting algorithms are measured in swaps.
PATTERN CARD · SWAP — one address computation serves both elements (0 and 4 offsets); load both, store crossed; registers are free temp variables.
06 · Decisions, Twice

Two if Examples: == and <

Equality tests compile straight to bne/beq. Less-than needs a helper: slt writes 1 or 0 into a register, then a branch tests that. Two examples, same inversion habit: branch around the code when the test fails.

Why no "blt" (branch-if-less-than) in real MIPS? A magnitude compare is slower hardware than an equality check — it would stretch the critical path and drag fmax down for every instruction. So the contract splits it: slt does the compare (1 cycle), beq/bne do the jump. ISA design decisions are clock decisions.

EXAMPLE A · if (i == j) f = g + h; (i→$s3, j→$s4)

bne $s3, $s4, Skip # bail if i ≠ j add $s0, $s1, $s2 Skip: ...

Test inverted: the branch jumps over the body when the condition fails. IC = 2 on the taken path, 2 on the fall-through.

EXAMPLE B · if (a < b) f = 1; (a→$s1, b→$s2)

slt $t0, $s1, $s2 # $t0 = (a<b) ? 1 : 0 beq $t0, $zero, Skip addi $s0, $zero, 1 Skip: ...

The slt + beq $zero pair is the universal "<" idiom — note $zero earning its keep again as the free comparison partner.

Count the cost of a decision: Example B spends 3 instructions to guard one. In a hot loop, branches are also the CPI-2, stall-risk class from the clock lecture — which is why compilers sometimes replace tiny ifs with branchless slt arithmetic, and why "branchless programming" is a real optimization genre in game engines and crypto code.
PATTERN CARD · IF — invert the test, branch around the body. For </>: slt into a temp, then beq/bne against $zero.
07 · The Loop

Trace a while Loop, Iteration by Iteration

The search loop — while (A[i] != k) i = i + 1; — is five patterns glued together: address math, load, compare, branch, jump back. Pick a target k and single-step the machine through the array.

A loop is just an if that jumps backwards. Each pass: compute where A[i] lives, fetch it, compare to k — beq bails out when found, otherwise bump i and j back to the top. Watch the instruction counter: the loop body's price × the number of passes is where whole programs spend their lives.

08 · Calling For Help

Functions: jal, $ra, and the Deal

A function call needs three agreements written into the contract: where arguments go ($a0–$a3), where the result comes back ($v0), and how to find your way home ($ra). Two instructions run the whole show: jal and jr $ra.

jal Fee does two things at once: writes the return address (PC + 4) into $ra, then jumps to Fee. The function does its work and ends with jr $ra — "jump to whatever address is in $ra" — which lands exactly on the instruction after the call. It's leaving a bookmark before opening another book.

WORKED EXAMPLE · total = addFee(price) where addFee(x) returns x + 25

Caller sets up the argument: add $a0, $s1, $zero — copy price into the agreed mailbox $a0.
Make the call: jal AddFee — hardware silently does $ra ← PC + 4, then PC ← AddFee. The bookmark is placed.
The function (a "leaf" — it calls no one): AddFee: addi $v0, $a0, 25 — result goes in the agreed return mailbox $v0.
Come home: jr $ra — PC ← $ra, execution resumes right after the jal.
Caller collects: add $s2, $v0, $zero — total ← result. Whole round trip: IC = 5. Every function call in every language you've ever run is this handshake (plus a stack, when functions call functions — that's a later lecture).
This is why deep call chains cost real time: each call/return pair is overhead instructions that do no math. When a compiler inlines a small function — pasting its body into the caller — it's deleting the jal/jr handshake to cut IC. "Function call overhead" in your profiler is this slide, measured.
PATTERN CARD · CALL — args in $a0–$a3 → jal F (bookmarks $ra) → result in $v0 → jr $ra → caller reads $v0.
09 · The Grand Example

Full Translation: Sum an Array

Everything at once: sum = 0; for (i = 0; i < N; i++) sum += A[i]; — initialization, a compare with slt, the array pattern, and a backwards jump. This is the shape of most real computation on Earth.

Read it as three zones: setup (2 instructions, runs once), loop body (8 instructions, runs N times), exit check (2 instructions, runs once more to discover it's done). Total IC = 8N + 4 — the N term is everything; the constants are noise.
# sum→$s0, i→$s3, N→$s1, base of A→$s6 add $s0, $zero, $zero # sum = 0 add $s3, $zero, $zero # i = 0 Loop: slt $t2, $s3, $s1 # $t2 = (i < N)? beq $t2, $zero, Exit # bail when done sll $t1, $s3, 2 # 4×i add $t1, $t1, $s6 # &A[i] lw $t0, 0($t1) # fetch A[i] add $s0, $s0, $t0 # sum += A[i] addi $s3, $s3, 1 # i++ j Loop Exit:

Per pass: 7 one-cycle instructions + one lw at 4 = 11 cycles / iteration. Slide N up and watch the setup constants vanish into rounding — loops are where the Iron Law collects.

This ten-line loop is an audio filter, a grade-average calculator, a neural-network layer, a pixel pass in your Unity shader. Change what happens to $t0 in one line and it becomes any of them. When hardware designers say "make the common case fast," this loop is the common case.
10 · Speak It Better

Same Loop, Fewer Instructions

A fluent speaker looks at the loop and sees waste: recomputing the address from i every pass. Keep a moving pointer instead — march $t1 through the array 4 bytes at a time, and two instructions vanish from the body.

Instead of asking "where is A[i]?" every pass (sll + add), keep your finger on the current element and just slide it 4 bytes forward (one addi). Same answer, less math — the classic "strength reduction" a good compiler performs, done here by hand.

BEFORE · index arithmetic each pass · 8 / iteration

Loop: slt $t2,$s3,$s1 beq $t2,$zero,Exit sll $t1,$s3,2 add $t1,$t1,$s6 lw $t0,0($t1) add $s0,$s0,$t0 addi $s3,$s3,1 j Loop

11 cycles / iteration (7×1 + lw 4)

AFTER · moving pointer · 5 / iteration

# $t1 = &A[0], $t3 = &A[N] (once) Loop: beq $t1,$t3,Exit lw $t0,0($t1) add $s0,$s0,$t0 addi $t1,$t1,4 j Loop

8 cycles / iteration (4×1 + lw 4) — and the slt is gone entirely

Speedup =11 / 8=1.38× — same machine, same clock, same answer. Only the speaker improved.
At N = 10⁹ on a 3 GHz clock, that's 3.67 s → 2.67 s: a full second recovered by rewriting five lines. This is precisely what -O2 does to your C, what the JIT does to your Java (MAC286), and what Burst does to your Unity C# (MAC280). Compilers are fluent speakers of the contract — this course teaches you to check their work.
11 · Capstone

Capstone: Raw Memory → Running Program

Final boss. Four words sit in memory starting at 0x00400000. Decode them one at a time, then say what the program computes. Everything from both lectures funnels into this one exercise.

Work the recipe per word: top 6 bits → format → slice fields → name registers → read with "gets." Then zoom out: four instructions in a row are a program, and programs have meaning beyond their lines.
0x00400000: 20080005 0x00400004: 20090003 0x00400008: 01095020 0x0040000C: AE0A0000
Word 1: 20080005 → op = 001000 = addi (I-format). rs=00000 ($zero), rt=01000 ($t0), imm=5 → addi $t0, $zero, 5 — "$t0 gets 5."
Word 2: 20090003 → same opcode → addi $t1, $zero, 3 — "$t1 gets 3."
Word 3: 01095020 → op = 000000 → R-format, funct = 100000 = add. rs=01000 ($t0), rt=01001 ($t1), rd=01010 ($t2) → add $t2, $t0, $t1 — "$t2 gets 8."
Word 4: AE0A0000 → op = 101011 = sw. rs=10000 ($s0), rt=01010 ($t2), offset 0 → sw $t2, 0($s0) — "memory at $s0 gets 8."
Zoom out: the program computes 5 + 3 and stores 8 at the address in $s0. You just did, by hand, what a disassembler and a CPU decoder both do — and you can now read a program that was never written in any language, only in numbers. That's fluency.
This skill has a job title. Security researchers decoding firmware, engineers debugging a crash dump with no source code, historians resurrecting 1970s software from ROM chips — all of them are doing this slide. The contract outlives its programs, its programmers, and sometimes its companies.
12 · Checkpoint

Prove It — Quick Checkpoint

Mental math only. Click an answer for instant feedback.

Each question is one pattern card: Q1 → arrays, Q2 → reading, Q3 → branches, Q4 → loops & the Iron Law, Q5 → sll. Miss one → replay that slide's instrument.
Q1 · What byte offset reaches A[7] from the base of a word array?
Words are 4 bytes: offset = 4 × 7 = 28. The ×4 reflex should now be automatic.
Q2 · Before: $s0 = 10, $t0 = 4. After sub $s0, $s0, $t0, $s0 = ?
Destination first, "gets" at the first comma: $s0 ← 10 − 4 = 6.
Q3 · beq $t0, $t1, Skip executes while $t0 = $t1. What runs next?
Equal → branch taken → PC jumps to Skip. If they differed, execution would fall through to the next line.
Q4 · A loop body is 6 instructions and runs 1000 times, plus 4 instructions of setup/exit. IC = ?
IC = 6 × 1000 + 4 = 6004. And per the Iron Law, the 6 is worth optimizing; the 4 never is.
Q5 · Why does sll $t1, $s3, 2 compute 4 × $s3?
Left shift by n = multiply by 2ⁿ, in one cycle — binary place value doing real work. It's why array indexing loves power-of-2 element sizes.

The Six Patterns Card

Every program you will ever read or write in this course is these six patterns, composed. If you can produce each from memory, the practice room did its job.

Don't memorize programs — memorize patterns and the bill each one runs up. Fluency is knowing the skeleton before you start writing, and knowing the cost before you finish.
