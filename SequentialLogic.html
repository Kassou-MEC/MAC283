Overview

Sequential vs. Combinational Logic

Sequential logic's output depends on the present input AND the history of inputs. Combinational logic depends only on the current input. Try it below — same button, different behavior:

Combinational · no memory

Light switch → bulb

Output = f(input). Nothing is remembered.

OFF
Release the switch → the state is gone. It only mirrors the input.
Sequential · has memory

Push-button toggle lamp

Output = f(input, state). Each press flips the stored state.

OFF · presses: 0
The lamp remembers what happened before. That "remembering" is exactly what a flip-flop does.
Real life: a doorbell is combinational (rings only while pressed). A ceiling-fan pull chain is sequential (each pull advances OFF → LOW → HIGH → OFF: it stores state).

Key Characteristics of Sequential Circuits

  • Contain memory elements — typically flip-flops
  • Output depends on current input + current state
  • Require a clock signal for synchronization (synchronous systems)
  • Can remember information over time

Timing

Clocks in Digital Logic — live signal

A clock is a timing signal that coordinates operations. It alternates between HIGH (1) and LOW (0) at a regular interval — one full alternation is a clock cycle.

Frequency 2 Hz · period T = 1/f = 0.500 s
Why it matters

Controls when data is read, written, or changed.

Why it matters

Keeps every part of the system in sync — one drumbeat for the whole orchestra.

Why it matters

Drives synchronous systems: CPUs, memory, registers.

Real life: "3.5 GHz processor" on a laptop spec sheet means this square wave repeats 3.5 billion times per second. Slide the frequency up and imagine multiplying by a billion.
Timing

Anatomy of a Clock Cycle

  • Flat high ‾ : voltage HIGH (~1V in modern CPUs)
  • Flat low _ : voltage LOW (0V)
  • Rising edge ↑ (0→1): most flip-flops capture data here — like a camera shutter
  • Falling edge ↓ (1→0): some designs trigger here instead
  • At 1 GHz, the cycle _|‾|_ repeats 1,000,000,000×/second
Clock Signal: _|‾|_|‾|_|‾|_|‾|_|‾|_ (each |‾| is one clock cycle) F D E F D E ... (F=Fetch, D=Decode, E=Execute)
The camera-shutter rule: the rising edge is the precise instant when new instructions are captured, results are saved, and data moves to the next pipeline stage. Between edges, nothing "official" changes.
Memory Elements

Flip-Flops — the basic memory element

A flip-flop stores one bit (0 or 1) and holds its output until the clock tells it to change.

Key characteristics
  • One or more inputs, one or two outputs (Q and Q̅), and a clock input
  • Changes state only on a clock edge (rising or falling)
  • Used to store data, build registers, and implement finite state machines
Real-life analogies
  • Sticky note on your monitor: it keeps the value until you deliberately rewrite it
  • Whiteboard in MB44: the tutoring schedule stays up until someone erases and rewrites it at a scheduled time
  • Camera shutter: the photo (Q) shows the scene at the instant of the click, no matter what happens after
Scale check: a 64-bit register is literally 64 D flip-flops side by side. Your CPU's register file, program counter, and instruction register are all just arrays of flip-flops.
Memory Elements

Common Types of Flip-Flops (click a card)

D

Data / Delay

Stores the value on input D at the clock edge. The workhorse of CPUs.

T

Toggle

Flips its output on each clock pulse (when T=1). Great for counters.

JK

Jack-Kilby*

Combines SR + T behaviors. J=K=1 means toggle — no forbidden state.

SR

Set / Reset

Latch that stores based on S and R inputs. The simplest memory cell.

What the circuit is doing
  • CLK = 0: gates N1/N2 ignore D → flip-flop holds state (memory effect)
  • Rising edge 0→1: N1/N2 capture D. D=1 forces Q=1, Q̅=0; D=0 forces Q=0, Q̅=1
  • CLK = 1: captured value stays locked until the next rising edge
Challenge: set D=1, pulse, then set D=0 without pulsing. Q stays 1 — the flip-flop is ignoring you until the next edge. That's memory.
Scenario

CPU Instruction Execution — the fast, organized chef

Imagine your CPU as a chef cooking many dishes (instructions) at once. To keep everything smooth, it follows a strict clock rhythm and uses flip-flops (memory boxes) to remember what it's doing.

Inside the CPU
  • A clock generates high-speed timing pulses (millions–billions per second)
  • Pulses control when instructions start and finish
  • Flip-flops store temporary data: register contents, instruction bits, intermediate results
The two sticky notes
  • Instruction Register (IR) — holds the current instruction
  • Result Register — keeps the answer until it's saved to memory
Without the clock? Chaos — steps finish too fast or too slow. Without flip-flops? The CPU forgets what it was doing between steps.

Pipelining — like an assembly line

Modern CPUs don't wait for one instruction to finish — they overlap them. Step the clock and watch three instructions flow through.

Cycle 0 — pipeline empty.
Key moment

At cycle 3: Instr 1 is executing (E), Instr 2 is decoding (D), Instr 3 is fetching (F). Three jobs, one clock tick — more instructions finish faster.

Real life

Laundry! Washer (F), dryer (D), folding (E). You don't wait for load 1 to be folded before starting load 2's wash. Pipeline stages pass data through flip-flops between phases.

Scenario

Superscalar — multiple chefs in the kitchen

A superscalar CPU (like in your phone or laptop) can start 4–6 instructions per cycle by having multiple execution units (ALUs, load/store units).

Clock Cycle: 1 2 3 4 Instr. A: F → D → E Instr. B: F → D → E ← two started in cycle 1! Instr. C: F → D → E Instr. D: F → D → E ← at cycle 3: FOUR in progress at once
Pipelining

One assembly line, overlapping stages.

Superscalar

Several assembly lines running in parallel.

Real life

One cashier scanning while bagging = pipeline. Six checkout lanes open = superscalar.

Summary so far: Clock = keeps everything in sync · Flip-flops = remember data between steps · Pipelining = overlap for speed · Superscalar = multiple at once. Without these, your CPU would be slow, chaotic, and unreliable.
Physical Reality

Physically, what is the clock?

What it is
  • A tiny quartz crystal (same idea as a wristwatch) that vibrates at a fixed frequency when electricity is applied
  • The vibration generates a square-wave signal alternating between 0V and ~1V — the CPU's drumbeat
Where it lives
  • Distributed across the chip through copper wires — the clock tree, a fractal-looking network covering the whole die
  • Modern CPUs run multiple clock domains: cores at 3 GHz, cache at 2 GHz
If you could shrink yourself and walk on a CPU: the clock would look like blinking lights pulsing down wires, and flip-flops would be tiny black boxes (transistor clusters) updating on each pulse.
Physical Reality

Physically, what is a flip-flop?

  • A microscopic circuit of 6–12 MOSFET transistors (CMOS technology)
  • Built from logic gates (NAND/NOR), which are themselves made of transistors
  • MOSFETs switch billions of times/second, use almost no power when idle, and shrink to nanometer scale — modern CPUs pack 50+ billion transistors

Inside the Box

D Flip-Flop circuit (simplified NAND version)

Key components
  • D (data input): the bit to store — 0 or 1
  • CLK (clock input): controls when to capture D
  • N1–N4: NAND gates (built from transistors)
  • Q (output): the stored bit · Q̅: always the opposite of Q
Cross-coupling is the trick: N-gates feed each other's outputs back as inputs. That feedback loop is what physically "traps" the bit — the same idea, scaled up, gives you SRAM cache.
Hardware Design

Finite State Machines (FSMs)

A Finite State Machine is a mathematical model for designing systems that:

1 · States

Have a finite number of states — distinct modes like ON, OFF, WAITING.

2 · Transitions

Move between states based on inputs: button presses, sensor data, timers.

3 · Outputs

Produce outputs (actions/results) depending on the current state and/or input.

The hardware connection: FSMs are sequential logic circuits — they use flip-flops to track state. With n flip-flops you can encode 2n states.
Moore machine

Output depends only on the state. More stable, predictable timing, easier to design.

Mealy machine

Output depends on state AND input. Faster response, often fewer states, more compact.

Hardware Design

Moore vs. Mealy — side by side

Moore block diagram
Inputs → [Combinational Logic] → Next State ↓ [State Register (Flip-Flops)] ↓ [Output Logic] → Outputs

Output changes only on state transitions (clocked).

Mealy block diagram
Inputs → [Combinational Logic] → Next State ↓ + Outputs [State Register (Flip-Flops)]

Outputs computed asynchronously — input changes can affect outputs immediately.

Memory trick: Moore = only output from state. Mealy = "meal depends on what you order and where you are."

Checkpoint

Quick reasoning check (answers hidden)

Q1 — Timing

The traffic-light counter uses a 1-second clock cycle. How long until the system returns to Green?

4 clock cycles → 4 seconds. The counter walks 00 → 01 → 10 → 11 and wraps back to 00.

Q2 — Classification

Is the traffic-light controller a Moore or Mealy model? Why?

Moore — the output (light color) depends on the state only, not on any external input.

Q3 — Scaling

Your FSM needs 6 states (e.g., a washing machine: fill, wash, drain, rinse, spin, done). How many flip-flops?

3 flip-flops (2³ = 8 ≥ 6). Two would only give 4 states; two of the eight encodings go unused.

Q4 — Design choice

An automatic door must react the instant the sensor sees a person, even mid-state. Moore or Mealy?

Mealy — outputs can change within a state as soon as the input changes, giving faster response.
Real Hardware

Where does the traffic light's clock come from? The 555 timer

Typical clock source
  • 555 Timer IC (analog) or a programmable microcontroller (digital)
  • Frequency: 0.1 Hz – 1 Hz (one pulse every 1–10 s)
  • 0.2 Hz = 1 pulse / 5 s — common for light transitions
  • 1 Hz = blinking yellow at pedestrian crossings
Why so slow? Traffic lights hold each state for seconds/minutes, not nanoseconds — human reaction time (~1–2 s) demands slow, predictable changes.
Astable mode · the period formula

T ≈ 1.44 × (R₁ + 2·R₂) × C₁

  • R₁ — resistor between Vcc and Discharge pin (Ω); controls charge time of C₁
  • R₂ — resistor between Discharge and Threshold (Ω); controls discharge time
  • C₁ — capacitor between Threshold and GND (F); larger C = slower cycle

Pin 2 · TriggerStarts the ON phase when C₁ drops to ~⅓ Vcc
Pin 6 · ThresholdStops it when C₁ reaches ~⅔ Vcc
Pin 7 · DischargeEmpties the capacitor

Firmware Design

The Huffman Model — ROM + flip-flops

A method for building FSMs in hardware: flip-flops hold the current state, a ROM stores the entire control logic (the FSM's "truth table"). Widely used in firmware controllers: microwaves, printers, IoT devices.

+----------------+ Inputs + Current → | ROM | → Next State State | (logic table) | + Outputs +----------------+ ↓ [State Register] ( D Flip-Flops ) ↓ Next State (feedback loop)
  • 1. Inputs + current state form a binary address
  • 2. That address reads a ROM line: next state + outputs
  • 3. On the clock edge, flip-flops load the next state
  • 4. New state feeds back to the ROM — a loop, forever
Worked example · automatic door

Why ROM? Flexibility — reprogram the ROM to change behavior without rewiring, and complex state machines fit in tiny, cheap hardware.

Wrap-Up

What you can now explain to anyone

  • Sequential logic = output depends on input + history (state)
  • Clock = drumbeat; flip-flops capture on the rising edge (camera shutter)
  • Flip-flop = 1 bit of memory, 6–12 transistors; registers are arrays of them
  • Pipelining / superscalar = overlap + parallel instructions for speed
  • FSM = states + transitions + outputs; needs ⌈log₂(states)⌉ flip-flops
  • Moore = output from state only · Mealy = state + input
  • 555 timer: T ≈ 1.44 × (R₁ + 2R₂) × C₁ — mind the µF→F conversion!
  • Huffman model = ROM (logic) + flip-flops (state) in a feedback loop
